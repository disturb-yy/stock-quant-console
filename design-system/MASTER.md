# 量策前端设计系统 · MASTER

## 适用范围

本文是仓库级的可执行视觉规范：以 `design-system/DESIGN.md` 为样式基础，将其视觉方向、层级、布局节奏与组件模式转化为量策可直接实现的品牌方向、语义 token、排版、间距和组件基础。页面目标、信息架构、业务状态和页面级偏离由 `design-system/pages/<page>.md` 定义；Agent 的执行、审批与验收规则由 `design-system/frontend-ui-guidelines-revised.md` 定义。

## DESIGN 基础与本地映射

- `DESIGN.md` 是默认视觉样式的来源，所有 UI 工作均应先读取；它描述的是应保留的视觉逻辑，而不是可直接拷贝的外部品牌资产。
- 本文负责把这些逻辑转化为量策可用的 token、系统字体和组件尺寸。`DESIGN.md` 中出现的外部品牌名称、商标、专有字体、文案、截图与媒体均不得成为运行时依赖。
- 页面文档可以补充页面目标、信息架构与行为；若需要偏离 `DESIGN.md` 或本文，必须在页面文档的“明确覆盖 DESIGN / MASTER”中写明具体规则、原因和证据。
- 若 `DESIGN.md` 的视觉基础与本文的本地 token 发生冲突，应先更新本文的映射或经批准更新 `DESIGN.md`，不得在单个页面中临时择一执行。

## 设计原则

1. 默认使用深色中性画布，建立克制、可信、可复核的数据研究氛围。
2. 主品牌色只承担主行动、关键选中状态和少量关键数值。
3. 数据密度来自清晰分组、细分隔线、数字对齐和排版层级，不依赖压缩字号或装饰堆叠。
4. 市场涨跌、成功、错误和警告采用彼此独立的语义，不与品牌色混用。
5. 页面不得暗示保证收益；示例行情和指标必须清楚标记其数据性质。

## 语义色彩 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| canvas | #0B0E11 | 主背景 |
| surface | #1E2329 | 主要卡片 |
| surface-raised | #2B3139 | 嵌套面板、描边 |
| brand | #FCD535 | 主 CTA、关键数值、选中状态 |
| brand-active | #F0B90B | CTA hover / active |
| text | #F5F5F5 | 标题 |
| body | #EAECEF | 正文 |
| muted | #929AA5 | 辅助说明、表头 |
| market-up | #0ECB81 | 上涨及已确认的正向市场变化 |
| market-down | #F6465D | 下跌及已确认的负向市场变化 |
| line | #2B3139 | 深色界面分隔线 |
| surface-inverse | #F5F5F5 | 明确要求反相表面的区域 |

成功、错误和警告不复用 `market-up` 或 `market-down`；需要这些状态时，应使用现有组件语义，或按审批流程补充全局 token。

## 字体与排版

- `DESIGN.md` 的“展示/正文无衬线 + 可信的等宽金融数字”是字体层级基础；其中提到的 BinanceNova 与 BinancePlex 仅为研究对象，不可直接使用。
- 中文文案与导航：PingFang SC、Hiragino Sans GB、Microsoft YaHei、Noto Sans CJK SC、系统无衬线后备，承担展示、正文、按钮和导航的角色。
- 数字：SFMono-Regular、Consolas、系统等宽后备，并启用等宽数字，承担价格、比例、日期、统计值和金融数据的角色。
- 一级展示标题由页面文档定义，但中文标题默认不超过两行。
- 区块标题：40px / 700 / 1.25；移动端 30px。
- 卡片标题：18–20px / 650 / 1.45。
- 正文：16px / 400 / 1.8；辅助数据：12–14px / 500 / 1.5。
- 单段正文建议不超过约 34 个汉字宽。

## 间距、尺寸、圆角与层级

- 基准为 4px；常用间距为 8、12、16、24、32、48、80px。
- 区块默认使用 96px（窄屏 64px）垂直间距；研究工作台可由页面文档定义更紧凑的节奏。
- 卡片内边距默认 24px。
- 圆角使用 6px（按钮）、10px（普通卡）、14px（主要数据面板）。
- 不使用玻璃拟态或厚重阴影；深浅表面与 1px 细线负责层级。

## 通用组件规则

- 主按钮：金底深色字，最小高度 44px，圆角 6px。
- 次按钮：深卡片底、细线描边、浅色字；不抢占主 CTA。
- 数据卡：`surface` 背景、`line` 描边；关键数字使用等宽字。
- 选项卡：仅选中项使用金色文字和底部 2px 指示线。
- 数据表：行间以细线分隔；市场涨跌作为文本色，不使用大面积彩色底。
- 标签：使用中性深色或透明样式，不以大量 pill 制造层级。
- 所有输入均有可见 label；键盘焦点使用高对比 2px 金色外环。

## 数据可视化

- 图表必须服务于数据阅读，不作为装饰背景。
- 主轨迹、坐标、标签、图例和关键数值具有清晰层级。
- 图表网格线保持低对比；数值使用等宽字。
- 数据含义不能只依赖颜色。
- 示例或模拟数据必须在图形附近标明。

## 动效与减少动态

- 仅对操作反馈和状态切换使用 160–220ms 的轻微过渡。
- `prefers-reduced-motion: reduce` 下取消非必要过渡与平滑滚动。
- 不使用自动播放、闪烁式报价或情绪化背景动效。

## 响应式基础

- `>= 1024px`：使用完整导航及适合内容的多栏布局。
- `760–1023px`：精简导航和间距，按内容可读性减少列数。
- `< 760px`：主区块默认单列；密集数据区域可横向滚动，不压缩关键文字和数值列。
- 页面文档可在不改变全局断点体系的前提下定义具体折叠行为。

## 无障碍基础

- 提供语义化 landmark、可见焦点和具有文本含义的操作标签。
- 颜色不作为唯一信息来源；关键状态同时提供文字、符号、数值或结构提示。
- 正文、辅助文字和交互控件满足可读对比度。
- 页面文档负责补充具体组件所需的 ARIA 状态和播报行为。

## 全局反模式

- 不用品牌色承载长段正文或大面积背景。
- 不使用渐变光晕、玻璃拟态、装饰性 3D、巨型圆角或漂浮卡片瀑布流。
- 不使用收益承诺、虚构实时行情或无法解释的 AI 买卖建议。
- 不直接复制外部产品的商标、字体、文案、截图、图标或其他品牌资产。

## 变更边界

- 页面文档只有在明确标记“覆盖 DESIGN / MASTER”并说明原因时，才能偏离视觉基础或本文的具体映射。
- 页面文档未涉及的规则继续继承本文。
- 通用 UI Guidelines 约束执行和验收，不覆盖页面文档或本文的视觉决定。
- `design-system/DESIGN.md` 是视觉样式基础；本文是其在量策中的安全、可执行映射，而不是独立于它的第二套视觉方向。
