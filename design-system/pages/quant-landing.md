# 量策落地页 · 页面规范

## 页面目标

面向有自助研究习惯的中文个人投资者与小型投研团队，用“研究工作台已在眼前”的首屏说明量策如何把市场数据、量化因子和组合复盘组成连续、可复核的研究流程，并引导访客试用分析工作流。

本页是隔离的高保真 mock 原型。仓库当前没有可复用的前端应用、品牌资产或真实数据 API，也不接入注册、登录或交易流程。

## 继承规则

- 视觉方向、层级、布局节奏和组件模式继承 `design-system/DESIGN.md`；颜色、字体、间距、圆角、表面层级、基础组件和全局断点使用 `design-system/MASTER.md` 的本地实现映射。
- Agent 执行、审批与交付检查遵循 `design-system/frontend-ui-guidelines-revised.md`。
- 本页使用已采用的深色金融平台视觉基础，但不复制外部商标、字体、文案、媒体或专有视觉资产。

## 页面补充

- Hero 右侧使用模拟策略雷达面板，让信息密度和产品能力可被立即感知。
- 中文 Hero 标题为两句、每句 6–10 字；桌面使用 68px / 700 / 1.16，移动端使用 42px。
- 桌面内容最大宽度 1,280px；Hero 使用约 5/7 的文案/行情面板比例。
- 页脚前必须出现明确的风险披露，避免页面被理解为收益或交易承诺。
- 所有市场数据持续标记为“演示数据”，不得暗示实时行情。

以上均是对 DESIGN / MASTER 的页面级补充，不覆盖两者。

## 页面组件与状态规则

- Header：72px 高的深色粘性顶栏；桌面导航、登录入口、主要免费试用 CTA 和移动菜单。
- Hero：标题、简短说明、一个主要 CTA、一个次要 CTA、三项静态覆盖范围指标、模拟策略雷达。
- 市场雷达：三个可切换标签；切换仅改变原型中的标题提示，不请求网络。
- 能力卡：因子雷达、策略工坊、组合监控三个可扫描的能力入口。
- 研究闭环：三步过程与一个策略复核卡。
- FAQ：使用原生 `details` 展开和收起。
- 试用弹窗：所有输入具有可见 label；只提供本地校验和提交反馈，不提交网络请求。
- 原型不伪造联网加载；真实产品接入时，必须另行设计加载、空数据、计算失败和权限不足状态。

## 图表规则

- 折线图主要轨迹使用 `brand`；`market-up` 只标记已确认的正向市场变化。
- 图表位于策略雷达卡内，附近持续出现“演示数据”。
- 不绘制 K 线或声称真实价位，以免静态页面被理解为实时研究终端。

## 页面级响应式规则

- `>= 1024px`：完整导航、双栏 Hero、三列能力卡。
- `760–1023px`：精简导航和间距；Hero 可保持双栏；能力卡两列。
- `< 760px`：Hero 与雷达上下排列；指标单列；导航收进弹出菜单。
- 市场行在小屏横向滚动，保持数值列完整，不缩小关键文字。
- 弹窗宽度不超过视口宽度减去 32px。

## 页面级可访问性规则

- 提供跳至主内容链接和语义化 landmark。
- 标签页使用 `tablist`、`tab` 与 `aria-selected`。
- 移动菜单按钮维护 `aria-expanded`。
- 弹窗提交反馈通过 `aria-live` 宣读。
- 涨跌数值同时显示正负号，风险说明使用文字表达。

## 明确覆盖 DESIGN / MASTER

当前没有覆盖项。未来若需覆盖，必须在本节写明被覆盖的具体规则、原因和证据；未列出的规则继续继承 DESIGN / MASTER。

## 未决事项

- 进入生产开发前，需要产品方确认真实数据源、股票市场范围、用户权限和合规文案。
- 免费试用最终接到注册、演示预约还是邀请码流程，当前只展示交互形态。

## 页面验收

- 深色画布与单一金色主强调正确应用。
- 中文标题和正文符合中文阅读节奏。
- 主要 CTA 与次要 CTA 层级明确。
- 关键数据、演示标记和风险披露清楚可辨。
- Desktop 与 mobile 布局均符合本页规则。
- 页面不依赖第三方图片、字体、网络请求或品牌资产。
